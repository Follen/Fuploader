# 黑盒 HTTP 登录契约

本文件维护当前约束。早期托管 Chromium 方案保留在历史归档；不再作为默认认证入口。当前字段、官方链路证据和缺口统一见 [平台字段总表](../../../../fupload/references/platform-fields.md#blackbox)。

## 登录与持久化

默认使用纯 HTTP 手机验证码或微信扫码。业务命令不得隐式发送短信、打开浏览器或切换账号。手机号与验证码从 JSON stdin 读取，不放 argv；微信只返回二维码图片路径及不透明任务编号，由用户扫码。登录待办有期限，跨进程可查询。

保存的会话与待办使用当前 Windows 用户 DPAPI 加密、原子替换及进程锁。新登录只有作者与备份接口读验证成功后才替换现有会话。短信提交先记录尝试状态；超时或已提交的任务不得重复消费验证码。

每次业务进程首次使用时调用官方 restore_login 续期，核对用户身份与服务器有效期后保存；闲置时不运行后台任务。续期失败明确返回登录需求。forget 只清除本地状态，不调用远端退出。

本机官方配置只提供短信发送所需的设备风控凭据，不将其当作账号 Cookie。接口只允许固定官方 origin 与路由，不接收调用者传入的 Cookie、pkey、签名、账号配置路径或临时 COS 凭据。

## 写入与输出

不重放结果不确定的 POST、对象上传或版本删除。版本删除仅通过 GET 确认；再次出现时报告需核对。日志和结构化输出隐藏凭据、手机号、验证码、OAuth code、签名及私密导入串，保留公开正文与普通资源链接。

自动化测试覆盖续期身份校验、锁与加密、单次验证码提交、微信官方回退链、失败时保留旧登录、默认无浏览器路径，以及业务请求不自动重放。真实登录的具体证据与本地测试分开记录。
