# Fupload CLI 完整目标规格

## 目标

`fupload` 是由 Agent Skill 调用、也允许用户直接使用的 Go/Cobra 命令行。它把每次调用约束为一个可观察的新手盒子业务动作，并通过平台 adapter 隔离服务商实现。

## 命令能力

CLI 的平台是一级命令。新手盒子能力位于 `fupload newbee ...`：

- `plugin list`：列出当前作者插件及最新版本摘要。
- `plugin get`：读取一个插件的可编辑详情。
- `plugin create`：只创建插件元数据，不隐式上传版本。
- `plugin edit`：只编辑既有插件元数据，不隐式上传版本。
- `plugin publish-version`：只为既有插件上传一个新版本压缩包及 changelog。
- `backup list`：列出 Creator 可用于配置分享的已有云端备份，输出可选择的 `cloud_id`、名称、版本和内容摘要。
- `backup get`：按 `cloud_id` 读取一个云端备份，输出可直接整理为配置输入的插件关联、忽略项候选和角色候选，并剔除下载地址、ZIP、哈希及原始配置等隐私字段。
- `option categories`：从新手盒子公开元数据读取当前插件分类及层级。
- `option game-versions`：从新手盒子公开元数据读取当前可用游戏版本。
- `config list`：列出当前作者配置分享。
- `config get`：读取一个配置分享的详情。
- `config create`：调用新手盒子 release 语义，引用已有 `cloud_id` 创建配置分享。
- `config update`：调用新手盒子 update 语义，更新既有配置分享并可更换到另一个已有 `cloud_id`。

每个写命令只触发对应的单个最终业务动作。媒体上传若是该动作字段的必要前置步骤，必须由显式媒体输入触发并在输出中单独报告，不能顺带创建其他业务对象。

## 平台架构

命令层必须通过平台注册表取得实现。首版只注册稳定 ID `newbee`。未来网易 DD 的稳定平台 ID 为 `dd`，命令形态为 `fupload dd ...`；首版不注册不可用的 `dd` 伪实现。未注册平台返回机器可识别错误和非零退出码，不回退到默认实现。平台接口覆盖插件、备份和配置分享能力；未来网易 DD 能以新 adapter 注册，而无需修改新手盒子业务实现。

## 新手盒子会话

CLI 自动复用本机 NewBeeBox 已登录状态，完成业务请求所需的会话交换。用户无需通过本次 CLI 登录。找不到登录状态、会话过期且无法恢复、作者权限不足时必须给出可操作错误，但不得输出凭据。

## 输入、输出与帮助

所有写命令统一要求 `--input <path|->`。文件路径按扩展名读取 `.yaml`、`.yml` 或 `.json`；`--input -` 从标准输入读取一个 JSON 文档，方便 Agent 无临时文件调用。业务字段只在该结构化文档中表达，不再提供一套同义 flags，也不存在 flags 覆盖输入文件的优先级。

所有必填输入必须可由非交互式 Agent 调用提供。缺少输入、解析失败、存在未知字段或必填字段缺失时不发网络写请求，返回非零退出码并指出准确字段路径。写入 schema 必须带版本字段，以便未来兼容演进。

只读命令使用简单 flags 表达 ID、分页和过滤条件。所有命令支持 `--output human|json`，默认为 `human`；Skill 始终使用 `--output json`。JSON 顶层包含 schema 版本、platform、operation、success、data 或 error，字段命名保持稳定。人类输出不得泄漏敏感信息。

写命令收到通过本地校验的合法输入后立即执行，不要求 `--apply` 或交互式确认。所有写命令提供可选 `--dry-run`：完成本地文件、schema 和业务约束校验，输出脱敏的目标与请求摘要，但不发送媒体上传或最终业务写请求。CLI 不在 dry-run 中声称远端权限或枚举 ID 已验证。

根命令、平台/资源中间命令和每个叶子命令都必须提供：

- 一句话摘要和详尽说明；
- 参数、是否必填、格式和服务端含义；
- 至少一个可执行示例；
- 写命令的服务端效果、审核影响和主要失败条件。
- 写命令输入 schema 的字段表、YAML 示例和等价的标准输入 JSON 示例。

## 插件行为

创建和编辑必须支持新手盒子元数据字段，包括名称、分类、来源、简介、详情及格式、Logo、截图、分享状态、订阅等级和频道关联。编辑必须要求目标插件 ID。

发布新版本必须要求插件 ID、版本号、至少一个游戏版本和压缩包；支持 changelog 与频道关联。客户端在联网前校验扩展名为 `.zip`、`.rar` 或 `.7z` 且文件不超过 300 MB。上传请求允许至少 10 分钟。

同一目标版本在远端已经存在时，默认停止并报告冲突，不盲目覆盖。网络结果不确定时，重新查询远端版本后再决定是否允许重试。

## 配置分享行为

CLI 不扫描或上传本地 WoW 配置。`backup list` 只展示已通过客户端上传且 Creator 可选择的云端备份。

`backup get` 必须把服务端可能以 JSON 字符串或数组返回的备份字段规范化为稳定结构。已知插件关联保留 `mod_id`、`mod_name`、`mod_file_id`、版本显示名和更新类型；未知插件、材质、字体只输出名称；角色只输出账号名/账号 ID、服务器、角色名和 `role_id`。不得输出 ZIP/下载 URL、哈希、原始 WTF 内容或其他凭据。

配置创建必须要求用户已选择的 `cloud_id`，并支持标题、正文、正文格式、简介、封面、来源、公开状态、频道、订阅等级、价格、时间范围、已知插件关联、未知插件/材质/字体忽略项和角色选择。

配置更新必须要求发布记录 ID，并在更新前读取当前详情；未提供的新值保持当前远端值。若更换 `cloud_id`，调用方必须重新明确提供与新备份匹配的关联、忽略项和角色选择，不能沿用不兼容选择。

## 错误与安全

业务成功要求 HTTP 2xx 且响应 `code == 1`。错误输出保留 endpoint 名称、HTTP 状态、业务 code 和脱敏 message。token、一次性 code、resource token、author token 和预签名 URL 永不进入普通输出。

CLI 不提供删除命令，不绕过平台审核，不在未知平台或输入不完整时执行写请求。创建输入没有明确公开设置时保持私有。`plugin edit` 和 `config update` 固定把目标设置为公开；帮助与输出必须说明该动作可能提交或重新进入审核，而不是保证立即审核通过。`plugin publish-version` 保持单一版本上传动作，Skill 在版本成功后调用 `plugin edit`，确保整个更新工作流最终公开。
