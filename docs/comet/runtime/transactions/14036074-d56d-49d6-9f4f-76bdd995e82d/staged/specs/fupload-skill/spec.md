# Fupload Skill 完整目标规格

## 定位

Skill 的显示名严格为 `Fupload`。它是用户与发布流程的主要交互面，负责理解意图、补齐资料、核对目标并调用 `fupload` CLI；不得自行重写新手盒子 HTTP 请求。

## 意图路由

当用户没有明确动作时，Skill 询问用户要执行哪一种：

1. 上传新插件；
2. 发布已有插件的新版本；
3. 编辑已有插件说明或其他元数据；
4. 创建配置分享；
5. 更新已有配置分享。

用户已经明确动作时不重复询问菜单，直接调查目标并收集该动作缺少的资料。

## 资料整理

Skill 使用 CLI 的只读命令查询插件、版本、配置发布和云端备份。它把用户提供的正文、图片、压缩包、版本号、更新日志、分类和关联项整理成带 schema 版本的 YAML/JSON 输入，在写入前展示目标平台、动作、目标 ID、主要字段、文件路径/大小和预期公开或审核影响。调用 CLI 时使用 `--input <file>`，或把 JSON 通过标准输入传给 `--input -`；不拼接复杂业务 flags。

收集资料前先检查用户给出的项目目录或当前工作区中的 `.toc`、README、CHANGELOG、现有压缩包、图片和版本控制变更，从中提取可复用的名称、版本、说明和更新日志。只询问本地资料与 CLI 只读查询都无法确定的产品选择；不得把可调查字段逐项交给用户手填。

Skill 不猜测分类 ID、游戏版本 ID、目标插件、目标配置或云端备份；存在多个候选时向用户展示可区分摘要并让用户选择。

CLI 写命令合法输入即执行。Skill 必须在调用前展示脱敏后的执行摘要并取得用户确认；需要预检时可以先调用同一命令的 `--dry-run`，但不能把 dry-run 成功描述为线上权限或发布成功。

## 配置分享约束

创建或更新配置分享前，Skill 必须说明：配置需要先由用户在新手盒子客户端上传为云端备份。然后调用 `backup list` 取得真实候选并询问用户选择。没有可用备份时停止，提示用户先去客户端上传，不尝试本地打包或调用未支持的备份上传接口。

选定备份后，Skill 协助整理已知插件关联、未知插件/材质/字体忽略项和角色选择。更新时如果更换备份，重新整理这些选择。

Skill 使用 `backup get` 取得上述候选，不从 `backup list` 的计数猜测关联项；使用 `option categories` 和 `option game-versions` 查询当前平台选项，不硬编码 ID。

## 执行边界

CLI 层的每个写命令保持原子；Skill 可以把一个完整目标编排为多个原子命令。执行前一次性展示全部步骤并取得用户确认，随后顺序执行。上传新插件可以依次调用 `plugin create`、`plugin publish-version`，并在用户明确要求公开时调用 `plugin edit` 提交审核。任一步失败就停止，不执行后续命令，并报告已完成步骤、远端 ID 和恢复建议。

未明确要求公开时，Skill 保持新建内容私有。对已有内容的更新固定以公开为最终状态：修改插件说明通过 `plugin edit` 直接公开；插件新版本上传成功后，如有需要继续调用 `plugin edit` 设置公开；配置更新通过 `config update` 直接公开。平台返回审核中时如实报告“已提交审核”，不得说成“已公开且审核通过”。修改插件说明不会上传版本，上传版本之外的公开步骤必须在执行计划中列出。

CLI 返回错误时，Skill 解释缺失资料或可恢复失败；结果不确定时先用只读命令核对远端状态，不直接重复写入。Skill 不展示、保存或要求用户粘贴 token。

## 平台扩展

首版 Skill 只允许选择稳定平台 ID `newbee`，并调用 `fupload newbee ...`。未来网易 DD 使用稳定平台 ID `dd` 和 `fupload dd ...`；届时可以增加平台选择和平台特有资料问题，而不改写新手盒子流程。

## 帮助与示例

Skill 文档必须包含五类意图的触发示例、每类资料清单、CLI 调用顺序、失败恢复、配置备份前置条件和安全约束。它应优先通过 CLI `--help` 与结构化只读输出获取当前命令契约，避免在 Skill 中复制易漂移的隐藏默认值。
